## Findings considered and rejected (recorded so nobody re-audits them)

- Agent output rendered as bot Markdown — social-engineering surface only
  (`_handleBuiltinCommand` never fires on agent text; buttons cannot be
  forged) → hardening only, no plan.
- Chat media extension allowlist (`bot.ts:262`, `discord.ts:232`) —
  pathological-but-not-exploitable (post-split segment cannot contain `..`);
  cosmetic hardening, rejected for this bang.
- Resource-hardening items that are NOT breaking (A2A `readBody` size cap,
  queue cap, join/notify flood limits, reminder API token) — real, defensive,
  breaking-free; they stay tracked in the audit backlog rather than sneaking
  into the breaking-changes bang. Revisit in a follow-up hardening release.
- Setup/daemon/wizard hardening (`loginctl` env interpolation, fake
  `~/.local/bin/node` shim, unpinned template tarball, token echo in
  terminal) — pre-bootstrap surfaces, own work package later.
- `npm pack` ~485 MB unpacked (wizard binaries in `dist/wizard/`) — packaging
  hygiene, not an exploitable surface; separate packaging task.
- `a2a.card` config could hold operator-pasted secrets — "config is truth" is
  the documented policy; documentation caveat only, no code change.
